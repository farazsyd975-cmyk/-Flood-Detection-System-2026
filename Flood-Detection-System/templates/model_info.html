System Technical FAQ & Architectural Rationale

Key machine learning and hydrological engineering decisions

Q1: Why Random Forest over Neural Networks for this application?

Environmental tabular telemetry with 8 correlated features benefits from tree ensembles because they naturally handle non-linear decision boundaries without requiring millions of samples. Neural networks easily overfit on small tabular domains and act as black boxes, whereas Random Forest provides direct feature importance rankings and deterministic decision logic.

Q2: Why does rainfall and antecedent rain dominate feature importance?

In Punjab's alluvial floodplains, runoff behavior adheres to the USDA Curve Number theory: once antecedent rain ($R_{7d}$) saturates the upper soil layer, the infiltration rate drops to near zero. Any subsequent 24-hour rainfall ($R_{24}$) converts almost 100% into immediate overland flow and river channel surcharge.

Q3: How does the system handle missing real-time API values?

The Flask server implements a dual-mode data service. If Open-Meteo is unreachable, the system automatically falls back to verified historical regional baseline station norms for that exact Punjab district, while explicitly marking the data source as "Calibrated Regional Baseline" to maintain scientific transparency.
